# Разработка и архитектура

## Границы модулей

`frontend/src/app` — оболочка, маршруты, авторизация и CSS-переменные.
`frontend/src/features` — игры, футбол, активность, кошелёк, администрирование.
`shared/api.ts` — HTTP-клиент с CSRF, типы и форматирование. Строгий TypeScript,
ESLint и Prettier. Сервер определяет правила; UI только показывает ограничения
из зафиксированных настроек и формирует запросы.

`backend/app` — Flask factory и маршруты. `auth/service.py` управляет локальной
сессией и профилем; `integrations/auth.py` — единственная точка внешней авторизации.
`games/service.py` — права автора, загрузки, проверка обложек. `activity/service.py`
— аренда начислений. `admin/service.py` — управленческие операции и аудит.
`common` — валидация, права, отслеживание realtime-сессий.

`shared/models.py` — общие SQLAlchemy-модели, `shared/economy.py` — денежные
транзакции и расчёт ставок, `shared/config.py` — именованные начальные параметры.
`shared/db.py` — фабрика транзакций и SELECT FOR UPDATE. Этот пакет импортируют
backend и симулятор: копий правил нет.

`simulation/engine.py` ничего не знает о Flask, БД, ставках или Redis.
`scheduling.py` создаёт календарь и рассчитывает коэффициенты.
`worker.py` получает единственный PostgreSQL advisory lock, ведёт матч, сохраняет
результат, затем отдельной транзакцией рассчитывает ставки.

## Принятые решения

- PostgreSQL — источник истины. Redis хранит только последний снимок, статус процесса
  и транспорт Socket.IO. Потеря Redis не уничтожает деньги или историю.
- Целочисленные сотые доли исключают float из баланса и выплат.
- Единый порядок блокировок: матч → кошелёк; операции активности блокируют только
  кошелёк. Повторные выплаты и возвраты ограничены уникальным ключом.
- Первый вход сериализуется advisory xact lock по внешнему идентификатору;
  `external_id` дополнительно уникален.
- Временные метки — Unix seconds UTC (double precision). В UI отображаются локально.
- Теги — небольшой JSON-массив в игре, отдельный справочник тегов не нужен для
  запрошенной фильтрации по категориям. Ограничение: нет отдельной таксономии тегов.
- В рамках небольшой системы используется один Gunicorn worker с 120 потоками.
  HTTP и Socket.IO разделяют серверные сессии; Redis обеспечивает межпроцессную доставку
  от симулятора. При масштабировании HTTP потребуются sticky sessions для polling.
- Обложки декодируются Pillow и заново кодируются WebP. Исходные EXIF и иные вложенные
  данные не сохраняются. Имя пользователя не участвует в пути файла.
- Старые версии HTML неизменяемы и сохраняются. Старый iframe может продолжить работу.
- Журнал баланса и административный аудит защищены PostgreSQL-триггерами от UPDATE/DELETE.

## Где менять поведение

| Изменение | Место |
|---|---|
| Начисления, heartbeat, аренда | `backend/app/activity/service.py`, settings в БД |
| Стартовые очки | `shared/config.py: INITIAL_CREDIT` |
| Приём ставок, расчёт, возврат | `shared/economy.py` |
| Вероятности и коэффициенты | `simulation/scheduling.py`, `worker.py` |
| Состояния и восстановление | `simulation/worker.py` |
| Поведение игроков, физика | `simulation/engine.py` |
| Команды и тактики | `backend/seed.py`, админпанель, `Engine.decide/move/step` |
| Внешняя авторизация | `backend/app/integrations/auth.py` |
| Цвета и адаптивность | `frontend/src/app/styles.css` |

Новая тактика должна получить явную ветку в engine, проверку значения в
admin/service и вариант в UI. При изменении физики увеличьте SIMULATION_VERSION:
это изменяет ключ кеша коэффициентов. Открытые матчи используют снимок правил
и команд; для обновления кода дождитесь завершения текущего матча или отмените его.

## Добавление endpoint и страницы

1. Добавьте правило в сервис соответствующей области, принимающий SQLAlchemy Session.
2. В маршруте валидируйте JSON/форму, вызовите сервис, верните JSON. Не вызывайте commit
   внутри маршрута: транзакция заканчивается в after_request. Ошибки — DomainError.
3. Защитите административные действия `@roles('admin')`, не полагайтесь на скрытую кнопку.
4. Добавьте тип результата, страницу в features и Route в App.tsx.
5. Для денежных изменений используйте только change_balance с устойчивым уникальным ключом.
6. Добавьте сценарный тест и обновите docs/api.md.

## Миграции и зависимости

```bash
alembic revision --autogenerate -m descriptive_name
# Просмотрите сгенерированные операции, особенности constraints и данных.
alembic upgrade head
alembic check
```

Исходная миграция фиксирует схему, а не импортирует текущее metadata. Изменение
models не подменяет уже выпущенную миграцию. `requirements.lock` фиксирует точные
версии прямых и транзитивных Python-зависимостей, включая dev-инструменты.
Frontend использует `package-lock.json` и `npm ci`. После обновлений пересоберите
образы и повторите тесты на PostgreSQL.

## Изоляция игры и мост

Игровой hostname не получает host-only cookie приложения. nginx этого origin
отдаёт только HTML с CSP: `sandbox allow-scripts`, `default-src 'none'`,
`connect-src 'none'`, запрет iframe, object, форм, workers; inline scripts/styles,
data/blob изображения и медиа разрешены. На родителе также `sandbox="allow-scripts"`:
нет allow-same-origin, popup, downloads или top-navigation.

Backend добавляет мост перед содержимым через `shared/game_bridge.py`, сохраняя
standards mode. Старые демонстрационные документы поддерживает совместимая вставка
nginx. Читаемая версия протокола — `deploy/bridge.js`. Аналогичный сигнал выглядит так:

```js
const session = new URLSearchParams(location.hash.slice(1)).get('session');
addEventListener('pointerdown', () => parent.postMessage({type:'gamehub:input', session}, '*'));
```

Родитель проверяет `event.source === iframe.contentWindow`, тип сообщения и
идентификатор текущей сессии; `origin` непрозрачен и не используется как единственная
проверка. Сигнал не содержит секунд или очков. Полноэкранный режим запрашивает
контейнер родительской страницы. У игры нет доступа к cookies, DOM или API GameHub.

Браузерные сигналы не доказывают участие человека: вредоносный HTML может имитировать
свои сообщения. Защита ограничивает дублирование и учёт времени, но не гарантирует
защиту от автоматизации. Самонавигация iframe тоже ограничивается sandbox по правам,
но запрет сетевых API CSP не следует трактовать как сетевую изоляцию всего браузера.

Дополнительно launch выдаёт подписанный ticket на конкретный файл, действующий
5 минут и проверяемый через внутренний nginx auth_request. Без ticket файлы
не выдаются. Проверяется действующая серверная сессия; cookies приложения на
игровой hostname не отправляются. Завершённая сессия делает ticket недействительным.
Внутренний /internal/game-access не публикуется основным nginx. Логи игрового origin
отключены, чтобы не сохранять bearer ticket. Уже загруженная игра остаётся в памяти
браузера после окончания ticket — это не новая выдача файла.
